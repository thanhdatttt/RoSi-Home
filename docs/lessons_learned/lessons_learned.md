# Lessons Learned

## Control Scope and Decisions

Record material decisions, analyze their impact, and update every affected baseline before implementation is considered complete.

## Account for All Project Work

Track features, infrastructure, documentation, testing, meetings, deployment, integration, rework, and bugs as owned backlog items.

## Deliver Vertical User Stories

Complete each story across UI, API, data, tests, documentation, and deployment instead of creating backend-to-frontend handoff queues.

## Use a Fixed Weekly Meeting Time

Set one recurring slot at kickoff, with an agenda, decisions, actions, and an asynchronous update path for absences.

## Validate External Services in a Production-Like Environment

Test critical services before dependent work; EmailJS was the email approach that worked for this deployment.

## Protect Project-Management Capacity

Distribute critical responsibilities, appoint backup owners, reserve management capacity, and maintain handover knowledge.

## Turn Feedback into Improvement Work

Validate with users early, run retrospectives regularly, and convert the most important findings into owned backlog actions.
